# celebrity_hecaitou 使用指南

我会用“槽边往事”式的观察路径和表达节奏回答，但不会声称这是和菜头本人观点。涉及事实、价格、政策、人物现状、产品状态和高风险判断时，需要先查证；证据不足时只能说是风险信号，不能硬编。

这个 Skill 最适合写的不是“仿和菜头语气”的文章，而是这几类：

## 适合的文章类型

1. **日常观察类杂文**

   从一个小场景进入，比如一次排队、一次退款、一个聊天截图、一个公众号排版错误、一句读者留言，然后拆出人性、成本、责任和判断标准。

2. **公众号文章选题拆解**

   你有一个模糊想法，比如“AI(Artificial Intelligence，人工智能) 写作会不会毁掉作者”，它可以帮你把题目改成更可写的问题：谁省力了，谁承担后果，什么东西不能被工具代替。

3. **读者答疑类文章**

   尤其适合处理“我该不该”“帮我选一个”“我是不是错了”“我该怎么想”这类问题。它不会急着给答案，而会先拆：提问者是在求方法、求安慰、求现货，还是求免罪。

4. **平台、工具、商业机制评论**

   比如小红书、公众号、微博、AI 工具、知识付费、内容平台、推荐算法、付费社群。重点不是骂平台，而是看谁付费、谁省力、谁被激励变懒、谁承担售后责任。

5. **文章可信度审稿**

   很适合让它审一篇“看起来很硬核”的文章：检查排版痕迹、来源链、论证链、作者动机，以及是否只是材料拼贴。

6. **反鸡汤式自我判断文章**

   比如“我为什么不想再追热点”“为什么我不想去更大的平台”“为什么我不直接给推荐链接”。这类文章适合用它拆虚荣、懒惰、确定性冲动和责任转移。

不太适合：纯新闻快评、严肃政策判断、法律医疗金融建议、没有具体场景的宏大命题、纯技术教程、纯营销文案。它像一把小刀，适合剔鱼刺，不适合劈柴。

## 提示词怎么写

最好给它四样东西：具体入口、你想拆的问题、输出形式、边界约束。

通用模板：

```text
$celebrity_hecaitou

我想写一篇中文公众号文章。
具体入口是：……
我真正想讨论的问题是：……
目标读者是：……
请按“具体场景 -> 表面异常 -> 机制拆解 -> 荒诞比喻 -> 判断规则”的结构，帮我拆选题/写大纲/写初稿。
要求：不要写成鸡汤，不要宏大开头，不要只模仿毒舌，要把成本、责任和动机说清楚。
```

如果你要写文章初稿：

```text
$celebrity_hecaitou

请帮我写一篇公众号文章，题目暂定《……》。
入口场景：……
我想批评/讨论的不是某个人，而是这个现象背后的机制：……
文章希望有一点“槽边往事”式的松弛和锋利，但不要复刻原文句式。
请写 1200-1800 字，结尾给读者一个以后可复用的判断规则。
```

如果你要拆选题：

```text
$celebrity_hecaitou

我有一个模糊选题：……
请不要直接写文章，先帮我拆：
1. 可以从哪个具体小场景进入
2. 表面异常是什么
3. 背后的成本、动机、责任分别是什么
4. 哪些大词应该换成可观察动作
5. 最后能给读者什么判断规则
```

如果你要审稿：

```text
$celebrity_hecaitou

下面是一篇文章/草稿，请用“槽边往事”式的可信度审稿方法检查：
- 形式痕迹
- 来源链
- 论证链
- 作者动机
- 是否有 AI 味或材料拼贴感

请先指出问题，再给最小修改建议，不要重写全文。
```

如果你要写读者答疑：

```text
$celebrity_hecaitou

这是一个读者问题：……
请先判断这个读者是在求确定性、求捷径、求安慰、求工具判断，还是求写作能力。
然后用公众号答疑文章的方式回答。
要求：不要直接替他承担选择责任，要把判断标准讲出来。
```

最关键的一点：不要只说“帮我写一篇和菜头风格的文章”。这就像对厨师说“给我做一个高级菜”，听起来有要求，其实没有食材、没有火候、没有忌口。更好的提示词应该给一个小东西：一副耳机、一个按钮、一段排版、一句留言、一次退款、一个 AI 工具的承诺。

这个 Skill 的强项不在“像”，而在“把问题从好不好、该不该，改写成谁承担什么成本，什么行为不能撒谎”。
